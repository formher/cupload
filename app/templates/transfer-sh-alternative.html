qurl.sh

Coming from transfer.sh

qurl.sh keeps the workflow you already have in muscle memory: one curl --upload-file and you get an HTTPS link back. No account, no email address, no API key, nothing to install. 

$ curl --upload-file ./report.pdf https://qurl.sh
✔ Success - uploaded report.pdf (4.2 MB)
  Expires in 24 hours or after 1 download, whichever comes first

You can download your file at https://qurl.sh/a1b2c3d4e5f6a7b8/report.pdf

Is transfer.sh still working?

We do not run transfer.sh and will not pretend to know its current status — its availability has varied over the years, and anything we wrote here would be out of date by the time you read it. Check for yourself, in one command: 

$ curl -sI https://transfer.sh | head -1

If it answers, use it. If it does not, or if you would rather not build a pipeline on something whose uptime you have to keep checking, the rest of this page maps the workflow onto qurl.sh.

Translating the commands

The upload command is the same; only the host changes.

transfer.sh qurl.sh
curl --upload-file ./f.txt https://transfer.sh/f.txt curl --upload-file ./f.txt https://qurl.sh/f.txt
(filename in the path) curl -T ./f.txt https://qurl.sh — the path is optional, curl fills it in
-H "Max-Days: 5" -H "X-TTL: 5d" — also accepts s, m, h
-H "Max-Downloads: 1" -H "X-Downloads: 1"
(no equivalent) -H "X-Password: hunter2" — prompts before the file is served

Updating your shell helper

Most people carried some version of this in ~/.bashrc. Only the host needs to change — the arguments and the plain-text reply have the same shape, so anything that scraped the URL out of the response keeps working: 

transfer() {
  curl --upload-file "$1" "https://qurl.sh/$(basename "$1")"
}

Or a version that also accepts a pipe, which qurl.sh supports with no temporary file:

qurl() {
  if [ -t 0 ] && [ -n "$1" ]; then
    curl -T "$1" https://qurl.sh
  else
    curl -T - "https://qurl.sh/${1:-stdin.txt}"
  fi
}

$ kubectl logs my-pod | qurl pod.log

Where the two differ

Worth knowing before you switch, including where qurl.sh is the smaller of the two. The transfer.sh column describes what its documentation stated; check its own docs for anything current.

transfer.sh (as documented) qurl.sh
Maximum file size 10 GB {{ max_size_mb }} MB
Default retention 14 days 24 hours, or one download
Maximum retention 14 days 7 days
Password protection — Yes, X-Password
Burn-after-reading secrets — Yes, /secret (encrypted, key never stored)
QR code for a phone — Yes, drawn in the terminal
Browser viewer — Syntax highlighting, Markdown, images, PDFs
Self-hostable Yes, open source No
If you need to move more than {{ max_size_mb }} MB in one go, qurl.sh is the wrong tool. It is built for logs, dumps, configs and artifacts — the things you need off a server right now — not for disk images. Split the file, or use object storage.

What else qurl.sh does

Things that had no transfer.sh equivalent:

# Pipe straight from a command, no temp file
$ kubectl logs my-pod | curl -T - https://qurl.sh/pod.log

# Burn-after-reading encrypted secret
$ echo "my-api-key" | curl -d @- https://qurl.sh/secret

# QR code drawn in the terminal, to get a file onto your phone
$ curl https://qurl.sh/qr/a1b2c3d4e5f6a7b8/report.pdf

# Pretty-print JSON, YAML or XML
$ curl -F "file=@config.yaml" https://qurl.sh/pretty
