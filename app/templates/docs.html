qurl.sh

Documentation

qurl.sh is a free, no-signup service for uploading and sharing files straight from a terminal. One curl command gives you a short HTTPS link. Files are ephemeral — by default a file is deleted after a single download, or after 24 hours, whichever comes first.

There is no account, no email address, no API key, no SDK and nothing to install. curl, wget or httpie is the entire client. Maximum file size is {{ max_size_mb }} MB.

How do I upload a file from the terminal?

Run one command:

$ curl -T ./report.pdf https://qurl.sh

qurl.sh confirms the upload in plain text and hands back the link to share:

✔ Success - uploaded report.pdf (4.2 MB)
  Expires in 24 hours or after 1 download, whichever comes first

You can download your file at https://qurl.sh/a1b2c3d4e5f6a7b8/report.pdf
QR Code: https://qurl.sh/qr/a1b2c3d4e5f6a7b8/report.pdf
Try wget http://qurl.sh/a1b2c3d4e5f6a7b8/report.pdf

The byte count is worth a glance — it is how you spot an upload that was cut short rather than completed.

-T (long form --upload-file) tells curl to send an HTTP PUT. Because the URL has no path, curl appends the local filename for you. To store it under a different name, give the URL an explicit path: 

$ curl -T ./local-name.txt https://qurl.sh/remote-name.txt

Other clients

$ wget --method=PUT --body-file=./report.pdf -O - https://qurl.sh/report.pdf
$ http PUT https://qurl.sh/report.pdf < ./report.pdf
PS> Invoke-RestMethod -Uri https://qurl.sh/report.pdf -Method Put -InFile .\report.pdf

How do I upload command output without a temp file?

Pipe into curl with -T - and put the filename in the URL, since there is no local file to take a name from. qurl.sh accepts chunked uploads, so nothing is written to disk first: 

$ tail -n 500 /var/log/syslog | curl -T - https://qurl.sh/syslog.log
$ kubectl logs my-pod        | curl -T - https://qurl.sh/pod.log
$ pg_dump mydb | gzip        | curl -T - https://qurl.sh/mydb.sql.gz

An entire directory, streamed as a tar archive without ever touching disk:

$ tar czf - ./my-project | curl -T - https://qurl.sh/my-project.tar.gz

How do I make a file expire, or limit downloads?

Two optional headers control the lifetime of an upload.

$ curl -T ./file.txt -H "X-TTL: 1h" https://qurl.sh
$ curl -T ./file.txt -H "X-Downloads: 5" https://qurl.sh
HeaderFormatDefaultMaximum
X-TTL number + s/m/h/d, e.g. 90s, 6h, 7d 24 hours 7 days
X-Downloads integer 1 100

Values above the maximum are clamped rather than rejected. Whichever limit is reached first wins: a file with X-Downloads: 5 still disappears once its TTL expires, even if nobody downloaded it.

How do I password-protect a file?

$ curl -T ./file.txt -H "X-Password: hunter2" https://qurl.sh

Opening the link in a browser then asks for the password before serving the file. The password is stored only as a salted hash, never in plain text. Headers combine freely: 

$ curl -T ./report.pdf \
    -H "X-TTL: 2h" \
    -H "X-Downloads: 3" \
    -H "X-Password: hunter2" \
    https://qurl.sh

How do I download the file again?

$ curl -O https://qurl.sh/a1b2c3d4/report.pdf
$ wget https://qurl.sh/a1b2c3d4/report.pdf

Opening the same link in a browser behaves differently: source files are shown with syntax highlighting, Markdown is rendered, and images and PDFs are displayed inline. Add ?raw=true to force the raw bytes in a browser. Command-line clients always get the raw bytes, so scripts and pipes behave predictably.

Downloads are streamed, so a {{ max_size_mb }} MB file never has to fit in memory and curl and wget show an accurate progress bar.

How do I send a password or API key securely?

For text rather than a file, use the burn-after-reading secret endpoint:

$ echo "my-api-key" | curl -d @- https://qurl.sh/secret
Secret Link (Burn after reading): https://qurl.sh/secret/a1b2c3d4e5f6/<key>

The text is encrypted with Fernet (AES-128-CBC + HMAC-SHA256). The decryption key is part of the URL returned to you and is never stored on the server — only ciphertext is written to disk. The first successful read returns the secret and immediately destroys it; a second read returns 404. Maximum secret size is 1 MB.

How do I get a file onto my phone?

Ask for the QR code from the terminal and it is drawn as text, right in your shell — no image viewer needed, which matters when you are three SSH hops from a desktop: 

$ curl https://qurl.sh/qr/a1b2c3d4/report.pdf

Point your phone camera at the terminal and the download starts. The block drawing sets its own colours, so it scans on a light or a dark colour scheme; add ?ascii=true for a smaller plain-text version with no escape codes, which is what you want if you are piping it to a file.

Opening the same URL in a browser returns a PNG instead — useful when screen-sharing or presenting.

Viewing the QR code never counts as a download and never consumes the counter. The code encodes the plain download link, so with the default limit of one download the first person to scan it gets the file. Pair it with -H "X-Downloads: 10" if you are putting it on a screen in front of a room.

How do I share readable JSON, YAML or XML?

$ curl -F "file=@config.yaml" https://qurl.sh/pretty

Returns a link to a re-indented, readable rendering. Accepts .json, .yaml, .yml and .xml up to 5 MB. For anything larger, upload it as a normal file.

Recipes for servers, containers and CI

# Pull a log off a remote box over SSH, without scp
$ ssh me@server 'curl -s -T /var/log/app.log https://qurl.sh'

# Ship a failing CI artifact somewhere a teammate can read it
$ curl -s -T ./test-results.xml -H "X-TTL: 2d" https://qurl.sh

# Capture the URL in a shell variable
$ URL=$(curl -s -T ./build.log https://qurl.sh | awk '/^You can download/ {print $NF}')
$ echo "Build log: $URL"

# Get a file out of a running container
$ docker exec my-container curl -s -T /app/debug.log https://qurl.sh

A convenience function for ~/.bashrc or ~/.zshrc:

qurl() {
  if [ -t 0 ] && [ -n "$1" ]; then
    curl -T "$1" https://qurl.sh
  else
    curl -T - "https://qurl.sh/${1:-stdin.txt}"
  fi
}

Limits, privacy and retention

Default lifetime24 hours

Maximum downloads100
Maximum secret size1 MB
Maximum pretty-print size5 MB
Upload rate limit10 per minute per IP
Global rate limit50 per hour, 200 per day per IP

No account, email address or API key is required or collected. Every file is deleted automatically — on download-count exhaustion, on TTL expiry, or by an hourly sweep, whichever comes first. Secrets are encrypted with a key the server never sees, passwords are stored as salted hashes, and everything is served over HTTPS.

qurl.sh is deliberately ephemeral. Do not use it as durable storage or as a backup destination — everything uploaded is designed to disappear.

HTTP API reference

MethodPathPurpose
PUT/<filename>Upload a file, returns a plain-text URL
GET/<id>/<filename>Download a file, or view it in a browser
POST/<id>/<filename>Submit the password for a protected file
GET/qr/<id>/<filename>PNG QR code for the download link
POST/secretStore an encrypted burn-after-read secret
GET/secret/<id>/<key>Read and destroy a secret
POST/prettyUpload JSON/YAML/XML for pretty-printing
GET/pretty/<id>/<filename>View the pretty-printed document
GET/Landing page, or plain-text help for CLI clients

Status codes: 200 success, 400 bad request or invalid secret key, 401 wrong password, 404 missing, expired or already consumed, 411 missing Content-Length on a non-chunked upload, 413 too large, 429 rate limited.

Machine-readable formats: OpenAPI 3.1 spec · llms.txt · llms-full.txt
